# Nerde.com — Critical Review

**Reviewer:** Agent 10 (Critical Reviewer) — did not build any of this.
**Basis:** [MASTER_PROMPT.md](MASTER_PROMPT.md) as yardstick; all code read as-built in [app/](app/README.md); live queries against [app/db/nerde.sqlite](app/db/import-report.json); `npx vitest run` re-executed this turn (65/65 pass, 8 files).
**Date of evidence:** this review. All counts below are measured from the actual DB, not from the docs.

---

## Verdict

**The loop is mechanically complete but the MVP is not ready to validate the hypothesis.** Every DoD interaction works end-to-end (map → category → marker → place → save → add → verify → report → share), the engineering discipline is unusually high for a swarm build, and the tests are genuinely green. But the product fails at the two moments that decide the experiment: (1) the *place page payoff* — 0 of 17,953 published places have a photo, 17,951 have an empty address, and ~74% carry generic fallback names ("Drinking water" ×7,445, "Picnic table" ×4,771), so DoD step 10 ("see useful information and photos") fails on essentially every place a user can open; and (2) *cold start* — 4 of the 18 homepage category chips (climbing, basketball, table-tennis, swimming-spots) have **zero** places, and the map is empty outside 12 cities, so "Near Me" shows a blank map to almost every real visitor. On top of that, the abuse surface (anonymous instant-publish + X-Forwarded-For-spoofable rate limiting + unauthenticated orphan photo uploads) means the first spammer, not the first user, will define the launch. If launched as-is, the MVP measures "do people want an empty, spam-filled map" — not the hypothesis in MASTER_PROMPT §4. Fix the three blockers below (est. days, not weeks), then soft-launch.

## Top 3 — I would refuse to launch until fixed

1. **B1 — Hollow place pages.** 0 photos, 17,951/17,953 empty addresses, ~74% generic names. The "inspect a place" payoff that the entire product pivots on is empty; launching now trains the first cohort that Nerde has nothing to offer, and submits 12k thin pages to Google as a bonus.
2. **B2 — Open UGC write path + spoofable rate limiter + anonymous orphan photo hosting.** One motivated spammer can publish unlimited junk places (instantly live, instantly in the sitemap) and use Nerde as a free image host until the disk fills. Moderation is one admin and a 500-row queue.
3. **B3 — Cold-start contradiction on the first screen.** 4 of 18 homepage categories contain zero places; the map has data in only 12 cities; "Near Me" returns emptiness for almost every visitor on Earth. The experiment would measure the empty-state, not demand.

## Top 3 — the team will be tempted to build next, but shouldn't (§29 scope guard)

1. **SSR / Next.js rewrite ("for SEO").** The SPA weakness is real but the documented prerender path (build-time render of category + top-N place pages) captures 90% of the value at 10% of the cost. Trigger a rewrite only when crawl stats prove place-page indexation is failing — ARCHITECTURE.md §2.1 already says this; hold the line.
2. **PostGIS / server-side clustering migration.** Measured: world-bbox query 1.1 ms, attr-filter scan 16.5 ms at 17.9k rows. The cap problem (I1) is a *truncation-honesty* problem, fixable in SQL + one UI line. Migrating databases before 100k+ real rows is resume-driven development.
3. **Reputation scores, badges, OAuth/social login, native apps, LLM "natural-language search."** All explicitly in §29 or §8-future. The only metric that matters next is §26's "users add places without being asked" — every hour not spent on content density (B1/B3) and contribution friction (I3) is an hour spent avoiding the actual experiment.

## What is genuinely good

- **The contract discipline is real.** CONTRACTS.md is honored in code (route table, hash format, event whitelist), migrations are idempotent and transactional, and the import pipeline is the most careful thing in the repo: endpoint failover with backoff, on-disk caching, lifecycle-prefix filtering, access=private exclusion, never-invented booleans, community-engagement protection on re-import, deterministic stable slugs.
- **Security fundamentals are mostly right, verified, not vibes:** parameterized SQL everywhere (I found no interpolation), magic-byte photo validation, timing-safe scrypt with a dummy-hash on unknown users, honeypot with silent fake-201, content-type CSRF guard, xmlEscape on the sitemap, and **no XSS surface found** — map popups render through React `createRoot` (safe), and the only `dangerouslySetInnerHTML` is a static theme string in a chart primitive.
- **The Near-Me privacy claim checks out.** Coords are used only for a client-side flyTo and the transient bbox query; `near_me_used` carries no meta; nothing location-like is persisted (verified in [NearMeButton.tsx](app/src/components/NearMeButton.tsx), [events.ts](app/server/routes/events.ts), and the events schema).
- **Tests are honest** (65/65 re-run this turn, including security and contract tests) — with the single caveat that I2 shows a test can be contract-true and production-false at the same time.
- **Self-awareness in docs:** ARCHITECTURE.md names its own weaknesses (SPA indexation, json_extract, single writer) with quantified triggers and upgrade paths. This review found the docs more honest than the data.
